# 📋 Velo Architectural & Security Reviews

This directory and index catalog all architectural reviews, security audits, and technical evaluations of the Velo programming language, its compiler toolchain, and standard runtime.

Velo enforces strict claims integrity and audit transparency: **external independent reviews** (conducted by third-party auditors or security researchers) are strictly distinguished from **internal self-assessments** (conducted by core project maintainers). Internal self-evaluations are explicitly labeled as retrospectives and are never presented as independent scorecards.

---

## 🛡️ External Reviews (Independent)

*Currently, no third-party external security or architectural audit has been commissioned or completed.*

### Submitting External Reviews & Audits
We actively welcome independent security audits, academic evaluations, compiler benchmarks, and external reviews:
- **Security Vulnerabilities**: Please follow the coordinated vulnerability disclosure policy documented in [`SECURITY.md`](../SECURITY.md).
- **External Audits & Articles**: If your organization has published an independent review or evaluation of Velo, open an issue or pull request to link it under this section.

## 📜 Review Principles & Invariants

1. **Claims Integrity ([Invariant I83.1](../gaps.md#security-invariants-1))**: Every quantitative claim in project documentation must be backed by a committed reproduction script and dated results.
2. **Measurability ([Invariant I83.2](../gaps.md#security-invariants-1))**: A claim that cannot be measured is removed from user-facing documentation, not softened.
3. **Audit Transparency**: Internal maintainer evaluations are labeled as self-assessments with clear authorship, dates, and milestone boundaries.
